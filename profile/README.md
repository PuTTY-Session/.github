# PuTTY Session - SSH Client with Saved Sessions for Class Hosts

## About PuTTY

PuTTY is a small remote window for a host you already have permission to use: a course server, a home lab machine, or a study account the instructor named. PuTTY SSH is the everyday path. A PuTTY session stores host, port, and how you log in, so the next class does not begin with retyping. PuTTY keys belong to that saved profile when the course uses public-key login. PuTTY serial is there for a local adapter in a hardware lab. PuTTY telnet is there only when a brief still asks for it.

The habit is open, work, close. PuTTY SSH should feel like a named door, not a toolbox you rebuild each time. A PuTTY session should be labelled with the course, not with a joke. PuTTY keys should stay in a place you control. PuTTY serial should not be mixed into the same profile as the campus host. PuTTY telnet should stay rare.

Home and study both need a session you can stop. PuTTY SSH does not have to stay connected overnight. A PuTTY session can be duplicated for a second course. PuTTY keys can be replaced when the school rotates them. PuTTY serial can wait until the kit is on the desk. PuTTY telnet can wait until the worksheet says so.

## Key Features of PuTTY

- **SSH as the default door** – PuTTY SSH is what you use for the class host. Save it as a PuTTY session with a boring name. Keep PuTTY keys only if the instructor said to. Leave PuTTY serial and PuTTY telnet off that profile.
- **Named sessions** – A PuTTY session is a label plus settings. Duplicate it for a second course instead of editing the first until it breaks. PuTTY SSH settings stay visible. PuTTY keys stay attached to the right card. PuTTY serial stays on the hardware card. PuTTY telnet stays nowhere until asked.
- **Keys with care** – PuTTY keys are not a souvenir. Store them away from shared folders. A PuTTY session can point at them. PuTTY SSH will use them. If a key is lost, ask the course how to replace it. PuTTY serial and PuTTY telnet do not need those files.
- **Serial for the bench** – PuTTY serial is for a cable you can see. Keep a separate PuTTY session for baud rate and port. Do not test PuTTY SSH settings on that card. PuTTY keys do not apply. PuTTY telnet does not apply.
- **Telnet only on request** – PuTTY telnet exists because some worksheets still name it. Prefer PuTTY SSH everywhere else. Do not save PuTTY telnet as your default PuTTY session. Do not mix it with PuTTY keys. Leave PuTTY serial alone.

## Quick Start with PuTTY

1. **Open PuTTY** – Create a PuTTY session named after the course. Enter the host the brief gave you. Leave PuTTY serial and PuTTY telnet untouched. Decide whether PuTTY SSH will use a password or PuTTY keys.
2. **Save before you connect** – Save the PuTTY session first. Attach PuTTY keys only if you were told to. Confirm PuTTY SSH is the selected method. Ignore PuTTY serial. Ignore PuTTY telnet.
3. **Connect and check** – Open PuTTY SSH, log in, and run a harmless command the course already uses, such as listing your home folder. If it fails, close the window and reread the PuTTY session. Do not guess with PuTTY telnet.
4. **Do the homework, then leave** – Keep the shell only as long as the task. Log out. Close PuTTY. Your PuTTY session remains in the list. PuTTY keys stay where you put them. PuTTY serial stays for lab day.
5. **Tidy the list** – Delete a PuTTY session you no longer need. Keep PuTTY SSH profiles labelled. Keep PuTTY keys off USB sticks you lend out. Keep PuTTY serial and PuTTY telnet as separate, rare cards.

## Who Will Like PuTTY

- **Home users** – A home lab PC can be a PuTTY session on the same desk. PuTTY SSH is enough. PuTTY keys help if you repeat the login. PuTTY serial helps a hobby board. PuTTY telnet usually does not.
- **Remote workers** – A named PuTTY session is faster than retyping a bastion host. PuTTY SSH should be the only method you save. PuTTY keys should follow company rules. Skip PuTTY serial and PuTTY telnet unless the job says so.
- **Students** – Course hosts are why PuTTY SSH exists in class. Save one PuTTY session per module. Use PuTTY keys when the wiki says to. Touch PuTTY serial only in the hardware week. Touch PuTTY telnet only if the PDF still prints it.
- **Technicians** – Keep customer and lab profiles apart. PuTTY SSH for the agreed host. A clean PuTTY session list. PuTTY keys handled as secrets. PuTTY serial for the bench. PuTTY telnet almost never.
- **Creators** – If a render box is yours, a PuTTY session is a calm way to check a process and leave. PuTTY SSH only. No need for PuTTY serial or PuTTY telnet. PuTTY keys only if you already use them.
